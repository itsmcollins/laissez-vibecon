1.  **Privy Authentication & Wallet Creation**: Users authenticate with Privy. Upon their *first login/account creation*, an embedded crypto wallet (on Base Sepolia) must be automatically provisioned for them. This wallet will serve as their primary payment recipient.
2.  **Telegram-Initiated Account Linking**: If a user interacts with an agent via Telegram and is not linked, a record in  (including their Telegram ID, original message query, bot token, and chat ID) is created. A dynamic linking URL, including the agent's per-message price, is sent back to the user. After authenticating with Privy on the frontend using this link, their Privy ID and Telegram ID are linked in .
3.  **x402 Payment for Agents**:
    *   The Telegram webhook endpoint should *not* be directly protected by x402, but rather handle payment logic internally.
    *   When a linked user messages an agent, their Privy wallet (associated with their Laissez ID) will be used to make a payment to the agent creator's wallet.
    *   The agent creator defines the per-message price, which is displayed to unlinked users.
4.  **Agent Management**:
    *   Authenticated users can create agents. The agent creation form must include a  field for the agent.
    *   All agents created by a user should utilize the same wallet address (the one created during their Privy login) for receiving payments.
    *   Any linked user can message any agent on the platform; access is not restricted to the creator.
5.  **Seamless User Experience**:
    *   After a Telegram user completes account linking, the system should immediately confirm linking success in Telegram.
    *   The original query that triggered the linking should then be processed by the agent in the background, and the agent's response sent back to the user in Telegram.
    *   The welcome message for unlinked Telegram users should include the agent's custom name and price.
